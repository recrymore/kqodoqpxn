# Gift Radar V10.2 — единый интерфейс и лимиты

Полная сборка на основе V10.1. Все предыдущие реализованные функции сохранены. Главный администратор — 8677315356. Служебная группа, доставка, заявки партнёров и отдельная админ-панель сохранены.

## Установка

Загрузите все файлы архива в корень GitHub-репозитория, включая `.github/workflows/bot.yml`. Оставьте `BOT_TOKEN`, `SEE_API_KEY`, `LOG_CHAT_ID` (если настроен) в Repository Secrets. Остановите старый Workflow, запустите Tracker Bot V10, откройте новую кнопку `/start`, затем `/admin` → Система.

## Настройки по умолчанию

19 поисков и 10 индивидуальных проверок на пользователя в сутки, до 25 NFT в подборке, пауза 10 секунд отдельно между действиями каждого типа. Счётчики включают попытки, в том числе кэшированные и неудачные. Сброс в 00:00 UTC. Лимиты действуют и для владельца. Настройки изменяются в админ-панели. При выключенном рыночном источнике базовый поиск возвращает до 10 NFT за подборку, хотя элементы управления имеют одинаковый вид у всех.

Дневной бюджет 0,2 TON. Платные запросы по умолчанию выключены. После проверки актуального тарифа их можно включить в админ-панели. Перед каждым потенциально платным запросом резервируется 0,002 TON (тариф, показанный в кабинете пользователя); после ответа резерв корректируется по X-Request-Cost. При неизвестной цене или превышении цены 0,002 новые запросы останавливаются до смены суток. При бюджете меньше стоимости резерва новые запросы также останавливаются, даже если есть бесплатная квота. Это консервативный локальный предохранитель, не гарантия ограничения расходов со стороны поставщика: изменение цены, использование того же баланса другими приложениями, потеря базы или независимые экземпляры могут привести к дополнительным списаниям. Не подключайте несколько независимых экземпляров к одному бюджету. Учитывается только расход данного экземпляра, не общий расход аккаунта. Служебные ping/me не резервируют бюджет согласно документации. Методы раскрытия скрытого владельца не используются.

## Рыночный источник и права

Обычный поиск отделён от административных прав. Базовый поиск доступен подписчикам. Публичное использование рыночного поиска по-прежнему выключено по умолчанию до получения разрешения поставщика. После согласования соответствующий режим задаётся переменной `PUBLIC_MARKET_APPROVED=1` (Repository variable для Actions, переменная среды для хостинга). Режим предоставляет поиск характеристик и цен без выгрузки контактов. Индивидуальная проверка публичного владельца остаётся у владельца бота; обычные пользователи могут просматривать характеристики карточки и открывать оригинальную NFT. Админ-доступ проверяется сервером. Партнёрские заявки не запускают экземпляры автоматически. Атрибуция источника сохранена.

## Постоянный хостинг

Запуск: `python -u start.py`. Переменные: `BOT_TOKEN`, `SEE_API_KEY`, `WEBAPP_URL` (HTTPS origin), `HOST=0.0.0.0`, `PORT`, `DATA_DIR` (постоянный диск), при необходимости `LOG_CHAT_ID`. На GitHub Actions счётчики, лимиты и память могут сброситься при новом запуске; Workflow ограничен 30 минутами. Не используйте временный runner для финансового контроля после включения платного режима. На постоянном диске сохраняются история, настройки и расход. Не загружайте токены и базы данных в GitHub.

Проверка: `python -m unittest discover -v`. Реальное подключение и работа UI в Telegram после обновления не проверены.

### V9.3 — партнёрские заявки

## Обновление основного бота

1. Распакуй архив и замени файлы в корне репозитория, включая `.github/workflows/bot.yml` (скрытая папка). Старые архивы не нужны.
2. Оставь GitHub Secrets `BOT_TOKEN` и `SEE_API_KEY`. Не публикуй секреты и не вводи их в чат или форму заявки.
3. Останови старый запуск, запусти `Tracker Bot V10` и отправь `/start`. Используй новую кнопку Mini App (адрес туннеля меняется).

## Партнёрские боты

В приложении: Профиль → Партнёрский бот. Участник создаёт собственного бота в BotFather, вводит только его @username, отправляет заявку. В Telegram доступны `/partner @ExampleBot`, `/partners`, `/mirror` (справка). Заявка не даёт административных прав и не запускает бота автоматически.

Только владелец Gift Radar (8677315356) может использовать `/partners` для общего списка, `/partnerapprove ID`, `/partnerreject ID`, `/partneractive ID`, `/partnerdisable ID`. Для остальных `/partners` показывает только собственные заявки. Статусы: pending, approved, rejected, active, disabled. Статусы не запускают и не выключают процессы: они отражают ручное согласование и развёртывание. Список является реестром заявок, не статистикой активной аудитории.

### Ручное развёртывание согласованного экземпляра

Использовать только с разрешения владельца соответствующего Telegram-бота и при соблюдении правил Telegram. На постоянном хостинге разместить отдельный процесс с собственным HTTPS-адресом, отдельным токеном в защищённой конфигурации, отдельными PORT и DB_PATH. Общий постоянный диск для CONFIG_PATH и PARTNER_DB_PATH обеспечивает общие настройки оформления и реестр заявок. Для каждого согласованного экземпляра установить TRACKER_MIRROR_MODE=1; администратор во всех экземплярах фиксирован в исходном коде и равен 8677315356. MIRROR_ADMIN_ID больше не используется. Не передавать партнёрским экземплярам SEE_API_KEY. Базовый поиск и собственный каталог доступны без него; рыночный API и индивидуальная проверка владельца остаются только в тестовом режиме владельца основного бота. Подключение нового бота администратором в @ZergowNft должно быть согласовано с владельцем канала. Команда запуска `python -u start.py`.

Переменные: BOT_TOKEN (свой для каждого экземпляра), WEBAPP_URL (свой HTTPS-адрес), HOST, PORT, DB_PATH (отдельная база), CONFIG_PATH (общий файл), PARTNER_DB_PATH (общий реестр), TRACKER_MIRROR_MODE (1 для согласованного партнёра). Общие пути должны быть доступны только доверенному серверному оператору. Раздельные базы нужны, чтобы заявки доставки и поддержка не пересекались между ботами. Для централизованного обновления установи одинаковую версию исходников на каждом экземпляре. Доступ к хостингу, секретам и исходникам у партнёров не предусмотрен. Владелец токена может отозвать его через BotFather.

Автоматический приём токенов, создание экземпляров из заявки, перенаправление аудитории после блокировки и автоматическое переключение ботов не реализованы. Одобрение заявки не равно подтверждению прав на бота. Проверь согласие владельца до развёртывания. Не используй экземпляры для обхода ограничений платформы.

## Доставка и копирование

В боте: «Куда присылать NFT» → «Подключить группу» → «Копировать команду». В приложении: «Доставка NFT» → «Подключить свою группу» → «Скопировать команду». Вставь `/connect@... ...` в собственную группу от своего имени. Бот и ты должны иметь права администратора группы. Одноразовый код действует 10 минут. Без группы поиск из приложения остаётся в приложении, из бота приходит в чат. С группой оба режима доставляют подборки в группу; результаты приложения также видны в приложении.

## Ограничения

GitHub Actions запускается на 30 минут и не гарантирует постоянное хранение базы между запусками. Для партнёрских экземпляров необходим постоянный хостинг; автоматический деплой не входит в сборку. Общая история заявок и оформления требуют общего диска. Проверка на реальном хостинге и в Telegram необходима. Источник рыночных данных указан по правилам API. Полноценное публичное подключение рыночного API не включено.

Локальные тесты: `python -m unittest discover -v`.

## V9.4 — служебная группа

Создай отдельную приватную группу со своего аккаунта владельца Gift Radar, добавь бота администратором. Отправь `/logs_here` в группе (при необходимости `/logs_here@имя_бота`). Не отправляй команду от имени канала или анонимного администратора. В личном чате доступны только владельцу `/logs_status`, `/logs_test`, `/logs_off`. Для сохранения привязки между временными GitHub Actions запусками отправь в группе `/groupid` и сохрани числовой ID в repository secret `LOG_CHAT_ID`. Workflow уже передаёт эту переменную. Если отключаешь логирование насовсем, удали также этот Secret, иначе оно восстановится при новом запуске с пустой базой.

В группу отправляются только технические события: запуск HTTP-сервера, число запрошенных/найденных подарков, ошибки поиска и коды HTTP ошибок рыночного API, получение партнёрской заявки, отдельные ошибки доставки. Не пересылаются токены, личные сообщения, идентификаторы пользователей, контакты владельцев NFT, содержимое API-ответов или сырые логи. Проверяются права бота и владельца группы перед каждой фоновой отправкой; события ограничены очередью и частотой, поэтому при всплесках или недоступной группе часть уведомлений может быть потеряна. Подробные диагностические логи по-прежнему в GitHub Actions. Тесты локальные, живое подключение группы не проверялось.

## V9.5 — исправление команд логов
Команды `/logs_status`, `/logs_test`, `/logs_off` доступны владельцу и в группе, и в личном чате. Для привязки из личного чата: `/logs_here -1001234567890` (подставь реальный ID). Группа должна быть приватной, созданной владельцем, бот — администратором. Если команда отправлена анонимно, бот предложит безопасный способ подключения.

## V10 — отдельная панель управления

Отправьте `/admin` в личном чате основного бота. Старая клавиатура будет убрана, появится кнопка открытия отдельной Mini App (`/admin`). Это отдельный экран на том же сервере; второй бот или новый домен не нужны. Сервер проверяет подпись Telegram initData и фиксированный ID владельца при каждом запросе `/api/admin`. Без действительной подписи настройки недоступны. HTML-оболочка публична, данные — нет.

Панель: обзор текущей базы, оформление, обращения и ответы, заявки партнёров, квота, служебная группа и ручной каталог цен. Одобрение заявки не развёртывает бота. Старые текстовые команды сохранены для совместимости и аварийного управления. Команда `/gift` остаётся в основном боте. Обычный поиск и API-доступ не менялись. Для теста GitHub Actions переменные прежние; загружайте также новый `admin.html`. При перезапуске временного хостинга локальная база и настройки могут сбрасываться.
